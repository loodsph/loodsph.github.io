Uno dei miei (tanti) punti deboli quando si tratta di musica è la **produzione di un suono specifico**. Suonare qualcosa che ho in testa è un problema che, bene o male, conosco; costruire *quel* basso, *quel* synth o *quella* atmosfera partendo da una forma d’onda è un’altra storia. Quindi ho deciso di buttare giù una traccia techno.

L’orientamento è **melodic techno**: voglio una melodia riconoscibile, ma né armonia né melodia devono essere particolarmente complesse. Una buona parte del gioco deve stare nel **suono e nella sua evoluzione nel tempo**. L’obiettivo è quindi creare una traccia il più possibile da zero, cercando di non affidarmi a preset già pronti. Userò **Logic Pro**; arrivo da GarageBand, quindi almeno l’interfaccia non mi è completamente aliena.

C’è poi un’altra cosa che mi interessa. Questo sarà probabilmente un lavoro abbastanza lungo da attraversare stati d’animo diversi e voglio vedere se — e quanto — questi finiranno per influenzare le mie scelte musicali, soprattutto se riuscirò ad accorgermene mentre succede. Non farò neanche finta che, per quanto grezza possa venire, questa traccia non sia in qualche modo **un’espressione di me**.

Non ho nessuna intenzione di prendere il lavoro di qualcun altro, farne un remix e poi dire che vado a “suonare”. È perfettamente legittimo, eh, niente di male. Semplicemente **non è il mio**: se devo fare questa cosa, voglio almeno provare a capire cosa sto facendo.

Da qualche parte bisogna partire, quindi scelgo **Fa minore**. Una tonalità minore mi sembra abbastanza naturale per quello che ho in mente. Anche la struttura generale è già più o meno chiara: qualche minuto, due drop — il secondo più profondo — melodia abbastanza presente e armonia molto semplice.

Non voglio però trasformare questo post in “poi alla battuta 17 ho messo un hi-hat”. Terrò soprattutto quello che durante il percorso mi è sembrato interessante o poco ovvio. Che nel breakdown abbia senso togliere il kick posso arrivarci anche con le orecchie pulite; quello che mi interessa è capire **perché certe cose funzionano** e, magari, alla fine capire un po’ meglio anche cosa sto cercando quando apro un synth e mi trovo davanti cinquanta manopole.

# Batteria

Dopo un po’ di prove con il MIDI, per programmare un classico **kick four-on-the-floor** trovo lo **Step Sequencer** molto più comodo del Piano Roll. L’idea iniziale è una intro abbastanza lunga: partenza senza kick, progressiva aggiunta di elementi, qualche variazione, una prima apertura e poi la parte principale.

Creo due pattern di batteria diversi. Mi piacciono entrambi, quindi rimando elegantemente il problema al mio me futuro. Il problema più urgente è un altro: **il suono fa schifo**.

Dopo parecchi tentativi approdo alla classica **Roland 808**: cruda, semplice, cassa profonda e basse decisamente presenti. Inizialmente tengo tutta la batteria insieme; piccolo spoiler dal futuro: sarà una pessima idea. Più avanti finirò per dividerla almeno in **Drum, Kick, Impact Kick e Filtered Drum**. Separare il kick dal resto si rivelerà particolarmente utile non solo per il mix, ma anche per il sidechain.

# Basso: una cosa sola non basta

Quasi subito decido di dividere il basso in due elementi: **Sub bass** e **Mid bass**. Non devono fare la stessa cosa: il sub deve dare **peso**, mentre il mid bass deve dare **carattere**. Questa distinzione, che all’inizio era quasi una scelta estetica, diventerà una delle cose più importanti che imparerò durante il pezzo.

## Sub bass

Apro **Retro Synth** e decido di costruire il suono da zero. Mi trovo davanti una quantità abbastanza indecente di parametri, quindi prima di toccare tutto a caso provo almeno a capire le fondamenta.

### Oscillatori

Un oscillatore genera il segnale di partenza. Nelle loro forme ideali, onde diverse hanno contenuti armonici diversi: una sinusoide contiene soltanto la fondamentale, mentre triangle, square e soprattutto saw introducono progressivamente più armoniche.

Tradotto brutalmente: **meno armoniche = suono più puro; più armoniche = suono più ricco, ruvido e aggressivo**.

La cosa interessante è che in un sintetizzatore non sono necessariamente costretto a scegliere una sola forma d’onda. Posso avere più oscillatori contemporaneamente e sommare i loro segnali. Il risultato non è un “terzo oscillatore”: è la somma istante per istante delle ampiezze dei due segnali, che può produrre una forma d’onda risultante diversa da entrambe.

Questa cosa è decisamente più semplice da vedere che da spiegare.

<script>
(() => {
  const root = document.currentScript?.closest('.tsw-widget') || document.getElementById('ts-wave-mixer');
  if (!root || root.dataset.ready) return;
  root.dataset.ready = '1';

  const q = role => root.querySelector(`[data-role="${role}"]`);
  const waveA = q('waveA');
  const waveB = q('waveB');
  const freqA = q('freqA');
  const freqB = q('freqB');
  const gainA = q('gainA');
  const gainB = q('gainB');
  const freqAOut = q('freqAOut');
  const freqBOut = q('freqBOut');
  const gainAOut = q('gainAOut');
  const gainBOut = q('gainBOut');
  const canvas = q('scope');
  const play = q('play');
  const preset = q('preset');
  const status = q('status');
  const windowNote = q('windowNote');

  let audioCtx = null;
  let graph = null;
  let state = 'stopped';
  let canvasSize = {c:null,w:0,h:0,dpr:0};

  function sample(type, phase){
    const twoPi = Math.PI * 2;
    let cycle = (phase / twoPi) % 1;
    if (cycle < 0) cycle += 1;

    if (type === 'sine') return Math.sin(phase);
    if (type === 'square') return Math.sin(phase) >= 0 ? 1 : -1;
    if (type === 'sawtooth') return 2 * cycle - 1;
    if (type === 'triangle') return 1 - 4 * Math.abs(cycle - 0.5);

    return 0;
  }

  function fitCanvas(force=false){
    const dpr = Math.min(2,Math.max(1,window.devicePixelRatio || 1));
    const rect = canvas.getBoundingClientRect();
    const width = Math.max(1,Math.round(rect.width*dpr));
    const height = Math.max(1,Math.round(rect.height*dpr));

    if(force || width !== canvas.width || height !== canvas.height){
      canvas.width = width;
      canvas.height = height;
      canvasSize = {c:canvas.getContext('2d'),w:rect.width,h:rect.height,dpr};
      canvasSize.c.setTransform(dpr,0,0,dpr,0,0);
    }

    return canvasSize;
  }

  function visibleDuration(){
    const delta = Math.abs(+freqA.value-+freqB.value);
    const bothSine = waveA.value === 'sine' && waveB.value === 'sine';
    return bothSine && delta > 0 && delta <= 5 ? Math.min(2,2/delta) : 0.04;
  }

  function draw(){
    const {c,w,h} = fitCanvas();

    c.clearRect(0,0,w,h);
    c.fillStyle = '#0b0d11';
    c.fillRect(0,0,w,h);

    const rows = [h/6,h/2,5*h/6];

    c.strokeStyle = '#252a33';
    c.lineWidth = 1;

    rows.forEach(y => {
      c.beginPath();
      c.moveTo(0,y);
      c.lineTo(w,y);
      c.stroke();
    });

    c.fillStyle = '#9ca3af';
    c.font = '12px system-ui';
    c.fillText('OSC A',12,18);
    c.fillText('OSC B',12,h/3+18);
    c.fillText('A + B',12,2*h/3+18);

    const duration = visibleDuration();
    const fA = +freqA.value;
    const fB = +freqB.value;
    const aGain = +gainA.value;
    const bGain = +gainB.value;

    const colors = ['#59c3ff','#ff6b3d','#f3f4f6'];
    const amplitude = h/14;

    for(let row=0; row<3; row++){
      c.beginPath();
      c.strokeStyle = colors[row];
      c.lineWidth = 2;

      for(let x=0; x<=w; x++){
        const t = (x/w)*duration;

        const a =
          sample(waveA.value,Math.PI*2*fA*t)*aGain;

        const b =
          sample(waveB.value,Math.PI*2*fB*t)*bGain;

        const value =
          row === 0 ? a :
          row === 1 ? b :
          a+b;

        const y =
          rows[row] -
          value*amplitude;

        if(x === 0) c.moveTo(x,y);
        else c.lineTo(x,y);
      }

      c.stroke();
    }

    windowNote.textContent = duration >= 1
      ? `Finestra visualizzata: ${duration.toFixed(2)} s. Il terzo grafico rende visibile il battimento.`
      : 'Finestra visualizzata: 40 ms.';
  }

  function makeVoice(type,frequency,level,master,now){
    const osc = audioCtx.createOscillator();
    const gain = audioCtx.createGain();
    osc.type = type;
    osc.frequency.setValueAtTime(frequency,now);
    gain.gain.setValueAtTime(level,now);
    osc.connect(gain).connect(master);
    osc.start(now);
    return {osc,gain,type};
  }

  function replaceVoice(key,type,frequency,level){
    if(!graph || graph[key].type === type) return;
    const now = audioCtx.currentTime;
    const oldVoice = graph[key];
    const newVoice = makeVoice(type,frequency,0,graph.master,now);
    newVoice.gain.gain.linearRampToValueAtTime(level,now+0.02);
    oldVoice.gain.gain.cancelScheduledValues(now);
    oldVoice.gain.gain.setTargetAtTime(0,now,0.008);
    graph[key] = newVoice;

    setTimeout(() => {
      try{ oldVoice.osc.stop(); }catch(e){}
      try{ oldVoice.osc.disconnect(); oldVoice.gain.disconnect(); }catch(e){}
    },60);
  }

  function refresh(event){
    freqAOut.value = `${freqA.value} Hz`;
    freqBOut.value = `${freqB.value} Hz`;
    gainAOut.value = `${Math.round(gainA.value*100)}%`;
    gainBOut.value = `${Math.round(gainB.value*100)}%`;

    if(state === 'running' && graph){
      const now = audioCtx.currentTime;
      replaceVoice('a',waveA.value,+freqA.value,+gainA.value);
      replaceVoice('b',waveB.value,+freqB.value,+gainB.value);
      graph.a.osc.frequency.setTargetAtTime(+freqA.value,now,0.01);
      graph.b.osc.frequency.setTargetAtTime(+freqB.value,now,0.01);
      graph.a.gain.gain.setTargetAtTime(+gainA.value,now,0.01);
      graph.b.gain.gain.setTargetAtTime(+gainB.value,now,0.01);
    }

    draw();
  }

  async function start(){
    if(state !== 'stopped') return;
    const AudioContextClass = window.AudioContext || window.webkitAudioContext;
    if(!AudioContextClass){
      status.textContent = 'Il browser non supporta la Web Audio API.';
      return;
    }

    state = 'starting';
    play.disabled = true;
    status.textContent = 'Avvio dell’audio…';

    try{
      audioCtx = audioCtx || new AudioContextClass();
      await audioCtx.resume();
      if(state !== 'starting'){
        await audioCtx.suspend().catch(() => {});
        return;
      }

      const now = audioCtx.currentTime;
      const master = audioCtx.createGain();
      master.gain.setValueAtTime(0,now);
      master.gain.linearRampToValueAtTime(0.09,now+0.025);
      master.connect(audioCtx.destination);

      graph = {
        master,
        a:makeVoice(waveA.value,+freqA.value,+gainA.value,master,now),
        b:makeVoice(waveB.value,+freqB.value,+gainB.value,master,now)
      };

      state = 'running';
      play.textContent = '■ Ferma';
      status.textContent = 'Audio in riproduzione.';
    }catch(error){
      state = 'stopped';
      status.textContent = 'Non è stato possibile avviare l’audio.';
    }finally{
      play.disabled = false;
    }
  }

  function stop({announce=true}={}){
    if(state === 'starting'){
      state = 'stopped';
      play.disabled = false;
      play.textContent = '▶ Ascolta';
      status.textContent = announce ? 'Audio fermato.' : '';
      return;
    }
    if(state !== 'running' || !graph) return;
    state = 'stopping';
    play.disabled = true;

    const stoppedGraph = graph;
    graph = null;
    const now = audioCtx.currentTime;
    stoppedGraph.master.gain.cancelScheduledValues(now);
    stoppedGraph.master.gain.setTargetAtTime(0,now,0.012);

    setTimeout(async () => {
      for(const voice of [stoppedGraph.a,stoppedGraph.b]){
        try{ voice.osc.stop(); }catch(e){}
        try{ voice.osc.disconnect(); voice.gain.disconnect(); }catch(e){}
      }
      try{ stoppedGraph.master.disconnect(); }catch(e){}
      if(audioCtx?.state === 'running') await audioCtx.suspend().catch(() => {});
      if(state === 'stopping') state = 'stopped';
      play.disabled = false;
      play.textContent = '▶ Ascolta';
      status.textContent = announce ? 'Audio fermato.' : '';
    },80);
  }

  [waveA,waveB,freqA,freqB,gainA,gainB].forEach(el => {
    el.addEventListener('input',refresh);
  });

  preset.addEventListener('click',() => {
    waveA.value = 'sine';
    waveB.value = 'sine';
    freqA.value = '110';
    freqB.value = '112';
    gainA.value = '0.65';
    gainB.value = '0.65';
    refresh();
    status.textContent = 'Preset del battimento impostato: 110 Hz e 112 Hz.';
  });

  play.addEventListener('click',() => state === 'running' ? stop() : start());
  window.addEventListener('resize',() => { fitCanvas(true); draw(); },{passive:true});
  window.addEventListener('pagehide',() => stop({announce:false}),{once:true});

  fitCanvas(true);
  refresh();
})();
</script>

Qui si capisce anche perché parlare semplicemente di un’onda come più “morbida” o più “spigolosa” sia insufficiente. Posso partire da due segnali relativamente semplici e ottenere qualcosa di molto più complesso semplicemente cambiandone forma, livello o frequenza.

Una prova particolarmente interessante è impostare due sinusoidi entrambe a **110 Hz** e poi portarne una a **112 Hz**. Le frequenze sono quasi uguali, ma non identiche: alternano quindi momenti in cui si sommano e momenti in cui si cancellano parzialmente. Il risultato è quel movimento periodico del volume che viene percepito come **battimento**.

Per il sub, però, non mi serve qualcosa di spettacolare. Voglio soprattutto una fondamentale stabile, quindi finisco su una **triangle con una componente sinusoidale**. È una delle prime volte in cui mi accorgo che un suono non deve necessariamente essere interessante quando lo ascolto da solo: deve avere una funzione quando tutto il resto suona insieme.

### LFO

Qui inizialmente avevo capito poco. **LFO significa Low Frequency Oscillator**: un oscillatore a frequenza abbastanza bassa da essere usato principalmente per modulare automaticamente un altro parametro. Può modulare pitch, volume, panorama, filtro e molte altre cose; nel mio caso, quella che mi interessa di più è il **cutoff**.

Il cutoff stabilisce il punto oltre il quale un filtro comincia ad attenuare determinate frequenze. Non c’è necessariamente un muro netto: la velocità con cui il filtro attenua le frequenze dipende anche dalla sua pendenza, espressa in dB/oct. Nel **low-pass** che sto usando, in termini molto meno eleganti: **cutoff basso = suono chiuso e scuro; cutoff alto = suono aperto e brillante**.

Sul sub, comunque, decido di fare ben poco. Non ho bisogno di trasformarlo in un’astronave: rimane prevalentemente sulla fondamentale **F0** — nella nomenclatura predefinita di Logic — e il suo compito è dare peso, non diventare una seconda melodia.

### Sidechain

Questo invece mi interessa parecchio. Inserisco un compressore sul sub e gli dico di reagire non al basso stesso, ma al **kick**. Ogni volta che arriva la cassa, il livello del sub viene abbassato per un breve momento.

La spiegazione più immediata sarebbe semplicemente “arriva il kick → il basso si abbassa”, ma la cosa interessante è un’altra: non sto semplicemente abbassando il volume del basso, sto creando uno **spazio temporale** nelle frequenze basse. Per qualche millisecondo il kick può occupare quella zona senza dover combattere con il sub, che subito dopo ritorna.

Senza sidechain ho una sensazione di chiusura, quasi di essere *overwhelmed*. Quando il sub si ritrae per un istante, invece, arriva una specie di sollievo: l’equivalente acustico di ritagliarsi un attimo di silenzio in mezzo al rumore della vita.

Questa è una di quelle cose che diventano molto più intuitive appena si possono vedere e ascoltare.

  if(!root || root.dataset.ready) return;

  const q = role => root.querySelector(`[data-role="${role}"]`);

  const play = q('play');

  const toggleState = q('toggleState');

  const canvas = q('scope');

  const bpm = 124;
  const beat = 60 / bpm;
  const beatsPerView = 4;
  const scheduleAhead = 0.1;
  const baseSubGain = 1;
  const reducedMotion = window.matchMedia?.('(prefers-reduced-motion: reduce)').matches;

  let sideOn = true;
  let ctx = null;
  let graph = null;
  let timer = null;
  let nextKick = 0;
  let nextDuck = 0;
  let state = 'stopped';

  let canvasSize = {c:null,w:0,h:0,dpr:0};

  function fitCanvas(force=false){
    const dpr = Math.min(2,Math.max(1,window.devicePixelRatio || 1));
    const rect = canvas.getBoundingClientRect();
    const width = Math.max(1,Math.round(rect.width*dpr));
    const height = Math.max(1,Math.round(rect.height*dpr));

    if(force || width !== canvas.width || height !== canvas.height){
      canvas.width = width;
      canvas.height = height;
      canvasSize = {c:canvas.getContext('2d'),w:rect.width,h:rect.height,dpr};
      canvasSize.c.setTransform(dpr,0,0,dpr,0,0);
    }

    return canvasSize;
  }

  function envelopeAt(timeInBeat){
    if(!sideOn) return 1;

    const a = +attack.value / 1000;
    const r = +release.value / 1000;
    const minimum = 1 - (+amount.value / 100);

    if(a > 0 && timeInBeat < a){
      return 1 - (1-minimum)*(timeInBeat/a);
    }

    const x = timeInBeat-a;

    if(x >= 0 && x < r){
      return minimum + (1-minimum)*(x/r);
    }

    return 1;
  }

  function kickSample(t){
    if(t < 0 || t >= 0.26) return 0;
    const startFrequency = 145;
    const endFrequency = 48;
    const sweepDuration = 0.14;
    const k = Math.log(endFrequency/startFrequency)/sweepDuration;
    const sweptTime = Math.min(t,sweepDuration);
    const sweptPhase = 2*Math.PI*startFrequency*(Math.exp(k*sweptTime)-1)/k;
    const phase = t <= sweepDuration
      ? sweptPhase
      : sweptPhase+2*Math.PI*endFrequency*(t-sweepDuration);
    const gain = t <= 0.24
      ? 0.8*Math.pow(0.001/0.8,t/0.24)
      : 0;
    return Math.sin(phase)*gain/0.8;
  }

  function draw(playhead=null){
    const {c,w,h} = fitCanvas();

    c.clearRect(0,0,w,h);
    c.fillStyle = '#0b0d11';
    c.fillRect(0,0,w,h);

    const top = h*0.34;
    const bottom = h*0.76;

    c.font = '12px system-ui';
    c.fillStyle = '#9ca3af';
    c.fillText('KICK',12,18);
    c.fillText('SUB GAIN',12,h*0.52);

    c.strokeStyle = '#252a33';
    c.lineWidth = 1;

    for(let b=0;b<=beatsPerView;b++){
      const x = (b/beatsPerView)*w;
      c.beginPath();
      c.moveTo(x,0);
      c.lineTo(x,h);
      c.stroke();
    }

    c.beginPath();
    c.strokeStyle = '#ff6b3d';
    c.lineWidth = 2;

    for(let x=0;x<=w;x++){
      const total = (x/w)*(beat*beatsPerView);
      const t = total % beat;
      const kick = kickSample(t);
      const y = top-kick*(h*0.19);

      if(x===0) c.moveTo(x,y);
      else c.lineTo(x,y);
    }

    c.stroke();

    c.beginPath();
    c.strokeStyle = '#59c3ff';
    c.lineWidth = 2.5;

    for(let x=0;x<=w;x++){
      const total = (x/w)*(beat*beatsPerView);
      const t = total % beat;
      const e = envelopeAt(t);
      const y = bottom-e*(h*0.17);

      if(x===0) c.moveTo(x,y);
      else c.lineTo(x,y);
    }

    c.stroke();

    c.fillStyle = '#59c3ff';
    c.fillText(
      sideOn ? 'ducking attivo' : 'nessun ducking',

      h-12

    if(playhead !== null){
      const x = Math.max(0,Math.min(1,playhead))*w;

      c.strokeStyle = '#f3f4f6';
      c.globalAlpha = 0.45;
      c.beginPath();
      c.moveTo(x,0);
      c.lineTo(x,h);
      c.stroke();
      c.globalAlpha = 1;
    }
  }

  function nextGridTime(after){
    if(after <= startTime) return startTime;
    return startTime+Math.ceil((after-startTime)/beat)*beat;
  }

  function holdAndReturnToBase(now){
    if(!graph) return;
    const param = graph.subBus.gain;
    if(typeof param.cancelAndHoldAtTime === 'function'){
      param.cancelAndHoldAtTime(now);
    }else{
      param.cancelScheduledValues(now);
      param.setValueAtTime(param.value,now);
    }
    param.linearRampToValueAtTime(baseSubGain,now+0.025);
  }

  function rescheduleDucks(){
    if(state !== 'running' || !graph) return;
    const now = ctx.currentTime;
    holdAndReturnToBase(now);
    nextDuck = nextGridTime(now+0.035);
    scheduler();
  }

  function refresh(){
    amountOut.value = `${amount.value}%`;
    attackOut.value = `${attack.value} ms`;
    releaseOut.value = `${release.value} ms`;
    rescheduleDucks();
    draw();
  }

  function makeKick(t,master){
    const o = ctx.createOscillator();
    const g = ctx.createGain();
    o.type = 'sine';
    o.frequency.setValueAtTime(145,t);
    o.frequency.exponentialRampToValueAtTime(48,t+0.14);
    g.gain.setValueAtTime(0.8,t);
    g.gain.exponentialRampToValueAtTime(0.001,t+0.24);
    o.connect(g).connect(master);
    o.onended = () => {
      try{ o.disconnect(); g.disconnect(); }catch(e){}
    };
    o.start(t);
    o.stop(t+0.26);
  }

  function applyDuck(t,subBus){
    const minimum = baseSubGain*(1-(+amount.value/100));
    const a = +attack.value/1000;
    const r = +release.value/1000;
    const param = subBus.gain;
    param.setValueAtTime(baseSubGain,t);
    if(!sideOn) return;

    if(a > 0){
      param.linearRampToValueAtTime(
        Math.max(0.002,minimum),
        t+a
      );
    }else{
      param.setValueAtTime(
        Math.max(0.002,minimum),
        t
      );
    }
    param.linearRampToValueAtTime(
      baseSubGain,
      t+a+r
    );
  }

  function scheduler(){
    if(state !== 'running' || !graph) return;
    const now = ctx.currentTime;
    const horizon = now+scheduleAhead;

    if(nextKick < now-0.05) nextKick = nextGridTime(now);
    if(nextDuck < now-0.05) nextDuck = nextGridTime(now);

    while(nextKick < horizon){
      makeKick(nextKick,graph.master);
      nextKick += beat;
    }
    while(nextDuck < horizon){
      applyDuck(nextDuck,graph.subBus);
      nextDuck += beat;
    }
  }

  function animate(){
    if(state !== 'running') return;
    const bar = beat*beatsPerView;
    const elapsed = Math.max(0,ctx.currentTime-startTime);
    const position = (elapsed%bar)/bar;
    draw(position);
    raf = requestAnimationFrame(animate);
  }

    if(state !== 'stopped') return;
    const AudioContextClass = window.AudioContext || window.webkitAudioContext;

      return;

        return;

      const master = ctx.createGain();
      const subBus = ctx.createGain();
      const subOsc = ctx.createOscillator();
      const subLevel = ctx.createGain();
      const harmonicOsc = ctx.createOscillator();
      const harmonicLevel = ctx.createGain();

      master.gain.linearRampToValueAtTime(0.42,now+0.03);

      subLevel.gain.setValueAtTime(0.18,now);

      harmonicOsc.connect(harmonicLevel).connect(subBus);

      harmonicOsc.start(now);

      play.disabled = false;
      status.textContent = 'Audio in riproduzione.';

      else animate();

      state = 'stopped';
      play.disabled = false;
      status.textContent = 'Non è stato possibile avviare l’audio.';
    }
  }

      state = 'stopped';
      play.disabled = false;
      status.textContent = announce ? 'Audio fermato.' : '';
      return;

      try{

        stoppedGraph.harmonicOsc.disconnect();
        stoppedGraph.subLevel.disconnect();
        stoppedGraph.harmonicLevel.disconnect();

        stoppedGraph.master.disconnect();

Con il sidechain disattivato la linea blu rimane piatta: kick e sub occupano contemporaneamente lo stesso momento. Attivandolo compare invece il “buco” nel gain del basso.

I tre controlli fanno vedere anche qualcosa che inizialmente tendevo a considerare un dettaglio tecnico. **Amount** stabilisce quanto profondamente il sub viene abbassato, **Attack** quanto rapidamente avviene la riduzione e **Release** quanto tempo impiega il basso a tornare al suo livello normale. Se il release è molto corto il sub torna praticamente subito; allungandolo compare sempre più chiaramente il classico effetto di pumping.

È probabilmente la prima volta durante questo progetto in cui comincio a pensare al mix non come a una collezione di volumi, ma come a una gestione dello **spazio**.

## Mid bass

Per il mid bass torno su Retro Synth, ma qui posso permettermi molta più sporcizia: oscillatore principale **saw**, un secondo oscillatore per aggiungere altre armoniche, registro superiore al sub — attorno a **F1** — e pattern in sedicesimi con note molto corte.

### Velocity

La velocity è, semplificando, la “forza” della nota MIDI. Se programmo sedici note perfettamente equidistanti, identiche e con la stessa velocity, il risultato tende rapidamente verso:

**tatatatatatatatata**

che non è esattamente il groove umano che stavo cercando.

Differenzio quindi le velocity. La griglia rimane estremamente regolare, ma alcune note assumono più importanza di altre e il ritmo comincia a respirare un po’.

### Filter Envelope

Altra scoperta. Il **Filter Envelope** modifica automaticamente il cutoff del filtro ogni volta che viene suonata una nota. Usa i classici parametri ADSR: **Attack**, cioè quanto tempo impiega l’inviluppo a raggiungere il massimo; **Decay**, quanto impiega a scendere dopo l’attacco; **Sustain**, il livello mantenuto finché la nota rimane premuta; **Release**, quanto impiega a tornare alla situazione iniziale dopo il rilascio.

Con attack quasi immediato, decay corto e sustain basso posso far aprire velocemente il filtro all’inizio di ogni nota e richiuderlo subito dopo. Il basso diventa molto più **percussivo**.

### Overdrive

Finalmente posso anche rovinare il segnale in maniera produttiva. L’**overdrive** spinge il segnale fino a farlo uscire dalla zona lineare del circuito o dell’algoritmo: la forma d’onda viene deformata e compaiono **nuove armoniche**. Sul sub preferisco evitarlo; sul mid bass, invece, è esattamente quello che voglio.

Il **Drive** stabilisce quanto fortemente spingo il segnale nella distorsione: poco significa saturazione relativamente delicata, molto significa distorsione evidente. Il **Tone** cambia invece il carattere timbrico della distorsione. Ci sarebbero altri parametri. Francamente non li trovo abbastanza interessanti da parlarne.

Aggiungo poi un EQ per togliere al mid bass parte dello spazio già occupato dal sub e un sidechain meno aggressivo.

### Sub + Mid bass

A questo punto la divisione comincia finalmente ad avere senso: **il sub dà il peso, il mid bass dà la personalità**. E soprattutto capisco una cosa che, almeno in questo mix, continuerà a tornarmi utile: **la separazione in frequenza viene prima ancora del volume**. Se due strumenti cercano continuamente di occupare lo stesso spazio, abbassarne semplicemente uno non è necessariamente la soluzione.

### Piccole variazioni armoniche

La base rimane centrata su F. In alcuni punti sostituisco però qualche nota con **Ab, C ed Eb**, tutte note appartenenti a Fm7. Non sto realmente suonando un accordo Fm7 con il basso: sto usando quelle note in successione per introdurre piccole variazioni senza distruggere il pattern.

L’idea rimane: **cambiare poco, ma farlo sentire**.

# Automazioni: il suono non deve stare fermo

Questa è probabilmente una delle parti che mi affascina di più. Un synth può avere sempre le stesse note eppure sembrare cambiare continuamente grazie alle **automazioni**, che permettono di modificare un parametro lungo la timeline: cutoff, riverbero, volume, send, praticamente qualunque cosa. È una specie di performance scritta in anticipo.

Qui finalmente riesco anche a mettere a fuoco una distinzione che all’inizio continuava a sembrarmi sfuggente: **volume = quanto segnale; cutoff = quale parte dello spettro**. Aprendo progressivamente il cutoff un suono può perfino sembrare più forte senza che io tocchi il fader, perché improvvisamente tornano intere regioni di frequenze che prima erano attenuate. Ed è esattamente questo tipo di evoluzione che voglio nel pezzo.

# Breakdown: dividere finalmente la batteria

Più cerco di costruire tensione nel breakdown, più diventa evidente che avere tutta la batteria su una sola traccia mi limita. Creo quindi una **Filtered Drum**, togliendo kick e buona parte delle basse e lasciando soprattutto gli elementi ritmici più leggeri. In questo modo posso mantenere la sensazione di pulsazione mentre l’energia generale cala.

A questo punto mi ritrovo con **Drum, Kick, Impact Kick** — una cassa usata soprattutto per sottolineare alcuni ingressi —, **Filtered Drum, Mid bass e Sub bass**.
Ascolto.
**È tutto molto peggio del previsto.**

# Lead, spazio e riverbero

A questo punto mi serve qualcosa che dia atmosfera al breakdown. Non voglio un’altra parte melodicamente complicata, quindi costruisco un **lead molto semplice** con Retro Synth: due saw leggermente detunate — circa +6 cent — attack relativamente lento, release lungo e note lunghe in tonalità.

Più che una vera melodia deve comportarsi come una presenza. 

## Il riverbero e la scoperta dei bus

Qui cambio approccio. Potrei mettere ChromaVerb direttamente sul lead, ma invece utilizzo un **Send**. Il segnale originale continua normalmente verso lo Stereo Out, mentre contemporaneamente ne mando una copia a un **Bus**, che alimenta un canale Aux con ChromaVerb.

Sul riverbero imposto Dry 0%, Wet 100%, decay lungo, pre-delay e damping di basse e alte. In pratica ottengo due percorsi separati: il **lead dry** e la sua componente riverberata.

La cosa diventa interessante nelle pause, perché posso interrompere completamente il lead originale mentre la sua **coda riverberata continua a esistere**. Il silenzio quindi non è veramente vuoto, ed è molto più interessante di aggiungere continuamente qualcosa.

# Il riff: quando complicare le cose peggiora tutto

Sul riff perdo un quantitativo di tempo che preferisco non quantificare. Cerco di costruire anche qui il suono da zero, finché a un certo punto apro Alchemy e trovo **Blockhead**.

Mi piace e lo uso.

Non senza essermi prima cosparso il capo di cenere dopo aver dichiarato all’inizio che avrei cercato di evitare i preset. Il purismo è durato abbastanza e non è una buona idea.

Adesso serve una progressione armonica. Provo:

**Fm → C**
poi:
**Fm → C7**

La dominante crea molta tensione verso Fm, ma l’E naturale mi porta verso un colore che in questo pezzo non mi piace. Provo anche a inserire Bb.

Aggiungo cose.
Tolgo cose.
Aggiungo altre cose.
Non mi piace niente.

Poi realizzo una cosa piuttosto ovvia: **sto inutilmente complicando qualcosa che avevo deciso dovesse essere semplice**.

Torno alla scala di Fa minore naturale e la progressione diventa:
**Fm → Fm → Ab → Cm**
Fm è casa, Ab apre, Cm crea una tensione molto più morbida prima di tornare a Fm.
Ora ci siamo.

# Arpeggiator

Provo inizialmente a ripetere gli accordi manualmente. Funziona, ma non mi convince. Guardando un corso su Logic trovo **Arpeggiator** e mi si accende una lampadina: invece di scrivere tutte le singole note, posso tenere premuto l’accordo e lasciare che l’arpeggiatore ne costruisca il movimento interno.

Gioco con rate, velocity, durata delle note, direzione e pause della Grid. La cosa che voglio evitare è l’effetto arpeggio-trance perfettamente continuo, quindi lascio intenzionalmente alcuni spazi. Anche il silenzio è parte del groove.

# Rivolti e voice leading

Qui arriva probabilmente la scoperta armonica che mi è piaciuta di più. Un **rivolto** contiene le stesse note di un accordo, ma cambia quale di queste si trova nella posizione più bassa. Per esempio Ab maggiore può essere **Ab–C–Eb**, ma anche **Eb–Ab–C**: le note sono sempre le stesse, cambia soltanto l’ordine.

Questo mi permette di usare:

**Fm:** F – Ab – C<br>
**Ab/Eb:** Eb – Ab – C<br>
**Cm/Eb:** Eb – G – C

Succede una cosa molto elegante. Da Fm ad Ab cambia praticamente una sola voce, **F → Eb**, mentre Ab e C rimangono ferme. Poi, da Ab a Cm, **Ab → G**, mentre Eb e C rimangono ferme.

Questo è **voice leading**: organizzare gli accordi in modo che le singole voci si muovano il meno possibile e in maniera coerente. Con l’arpeggiatore la differenza è enorme: gli accordi smettono di sembrare tre blocchi separati e diventano quasi **lo stesso oggetto armonico che si trasforma lentamente**.

Per l’EQ del riff non ho niente di filosoficamente interessante da dire: ho tolto quello che rompeva le scatole al basso. Fine.

Sul riverbero uso invece lo stesso sistema del lead, cioè **Send → Bus → riverbero 100% wet**. In più automatizzo il Send: avvicinandosi alle pause mando progressivamente più riff nel riverbero, poi interrompo il MIDI. Il suono sparisce, la coda rimane.

# Melodia, atmosfera e arrangiamento

Qui accorpo diverse cose perché, prese separatamente, non hanno una storia particolarmente interessante. La **melodia** rimane volutamente semplice e completamente coerente con la tonalità. Il riff è già molto attivo, quindi non mi serve una seconda mitragliatrice di note sopra: preferisco una frase riconoscibile che possa tornare nel pezzo con variazioni relativamente piccole. Cambio qualche finale, qualche durata e valuto l’ottava superiore nei momenti più intensi (spoiler: forse ci stava bene, ma non mi ha convinto), ma la regola rimane sempre la stessa: **meglio riconoscere una melodia che sentirne continuamente una nuova**.
Comunque, esperimento interessante. Sono sempre stato abituato a trovare le melodie con la chitarra in mano e lì succede una cosa diversa: c’è un miscuglio di testa, memoria muscolare e flow. Spesso tiri fuori una frase prima ancora di averla davvero pensata e, quando funziona, riesci quasi a sorprenderti da solo.

Qui molto meno. Nel piano roll non hai le dita che vanno da qualche parte per abitudine, non hai una diteggiatura che ti suggerisce il passaggio successivo e non hai lo stesso tipo di improvvisazione fisica. Devi immaginare molto di più la frase prima di costruirla. Non dico che sia necessariamente peggio, ma un po’ lo è.

Aggiungo anche una specie di drone sulla tonica F, una nota sostanzialmente ferma mentre gli accordi cambiano sopra. L’idea è avere una sorta di atmosfera **senza una vera risoluzione armonica**. Capisco che sia una supercazzola, ma non sapevo come dirla. Voglio che la saw cresca fino al drop e che duri "più di quanto ci si aspetterebbe". Il fall successivo (scendo di pitch e di cents) deve essere un pugno nello stomaco. Non sono soddisfattissimo del risultato, ma questo è.

Più precisamente, F continua a ribadire il centro tonale senza introdurre una nuova progressione. Costruisco il suono con Retro Synth, molto graffiato, quasi da interferenza, e lo lascio sullo sfondo per buona parte del brano facendolo aumentare progressivamente verso il secondo drop.

Per quanto riguarda l’arrangiamento, idem con patate. La struttura si è praticamente costruita mentre lavoravo sui suoni. La scelta più evidente è quella di preferire **tensioni relativamente lunghe e drop più brevi**, ma soprattutto comincio a usare il vuoto in maniera deliberata. Prima di un drop, mezzo beat o un beat quasi completamente vuoto può fare più di tre riser, due crash e un’esplosione nucleare.

La cosa interessante è che, man mano che il progetto va avanti, mi accorgo di aggiungere sempre meno e comincio invece a chiedermi: **cosa posso togliere?**

# Mix: aggiungere una traccia alla volta

Pensavo che il mix sarebbe consistito nel regolare qualche fader. Ovviamente no.

Per prima cosa tolgo qualsiasi mastering dal master bus e lascio lo **Stereo Out a 0 dB**. Parto dalla sezione più piena del pezzo, l’ultimo drop, e costruisco il mix aggiungendo un elemento alla volta.

Comincio da **Kick + Sub** e cerco prima di tutto il rapporto fra loro. Il kick deve dare l’attacco, il sub deve prolungarne il peso. Quando il rapporto mi piace, abbasso entrambi della stessa quantità: il loro equilibrio relativo non cambia, ma creo **headroom**, cioè margine prima dello 0 dBFS.

Aggiungo quindi il mid bass e continuo ad accenderlo e spegnerlo. La domanda diventa molto semplice: *quando entra, il basso acquista personalità o diventa semplicemente più grosso?* Quando la risposta è “personalità”, mi fermo.

Poi aggiungo la batteria e improvvisamente il livello sullo Stereo Out sale molto più di quanto mi aspettassi. Comincio mentalmente a preparare EQ, compressori e spiegazioni complicatissime.

Poi mi accorgo che avevo lasciato il kick anche nella vecchia traccia Drum.

Quindi:

**Kick dedicato + kick dentro Drum.**

Due casse contemporaneamente.

Tolgo quello duplicato.

Problema risolto.

Probabilmente uno dei momenti didatticamente più utili dell’intero progetto: **prima di cercare di risolvere un problema con un plugin, controllare che non sia semplicemente un errore di routing o arrangiamento**.

Continuo poi aggiungendo **Riff → Melodia → Lead → effetti**, sempre un elemento alla volta. Alla fine ascolto l’intera canzone: nessun clipping, Stereo Out sempre a 0 dB e picco massimo del premaster intorno a **−3,7 dBFS**.

Non mi interessa raggiungere religiosamente −6, −3 o qualunque altro numero. Mi interessa semplicemente lasciare del margine ed evitare di arrivare già schiacciato alla fase successiva.

# Mastering

Sono molto tentato di usare direttamente **Mastering Assistant di Logic**. E forse sarebbe stato anche più semplice. Ma dopo aver già ceduto sul preset del riff decido almeno di provare questa parte manualmente.

Esporto quindi il premaster a **24 bit, normalizzazione off e senza mastering**, poi lo apro in un progetto nuovo con una sola traccia stereo.

## Prima misurare, poi toccare

Inserisco **Loudness Meter**. Il premaster completo è intorno ai **−20 LUFS Integrated**, con una Loudness Range molto ampia; misurando separatamente l’ultimo drop, però, il valore sale parecchio.

Ed ecco un’altra banalità che capisco meglio dopo averla vista: **il loudness dell’intera canzone non è il loudness del drop**. Se il pezzo contiene breakdown lunghi, pause e sezioni rarefatte, l’Integrated complessivo scenderà inevitabilmente. Quindi non ha molto senso guardare un numero e decidere che devo arrivare a X LUFS costi quel che costi.

## Adaptive Limiter

Inserisco **Adaptive Limiter**. Il compressore e il limiter sono parenti, ma non fanno esattamente lo stesso lavoro: un compressore riduce il livello sopra una certa soglia secondo un determinato rapporto, mentre il limiter viene usato soprattutto come barriera finale per impedire ai picchi di superare un certo tetto.

Imposto **Out Ceiling a −1 dB** e **True Peak Detection ON**, poi comincio ad aumentare il Gain. Più lo aumento, più il brano diventa forte, ma anche più il limiter deve modificare i transienti.

Provo prima **+5 dB** e suona bene.
Provo **+7 dB**, suona meglio.
A questo punto non ho altri parametri o conoscenze teoriche che non siano il mio gusto, mi devo arrangiare. Forse meglio così.

Non semplicemente perché è più forte: per confrontare davvero le due versioni compenso il livello in uscita, così il volume percepito non decide al posto mio. Nell’A/B il drop mi sembra più convincente senza perdere in maniera evidente l’impatto del kick. Quindi scelgo **+7 dB** e mi fermo lì. Nel drop arrivo grosso modo nella zona dei **−10 LUFS Short-Term**.

Potrei probabilmente spingerlo ancora, ma a quel punto la domanda non è più “posso?”. È **“perché?”**.

# Transparent mi tradisce

Per curiosità provo comunque **Mastering Assistant → Transparent**.

E mi piace.
Fastidiosamente.

Guardando cosa sta facendo capisco però che non è semplicemente una questione di loudness. Il suo Auto EQ suggerisce grosso modo una riduzione di parte delle basse, un leggero rinforzo dei medi e una lieve attenuazione delle frequenze più brillanti.

Decido quindi di usare Mastering Assistant non come soluzione finale, ma come **strumento diagnostico**. Prendo l’idea e la applico in maniera molto più leggera con Channel EQ: circa **71 Hz → −1,1 dB**, **670 Hz → +1,1 dB** con curva molto larga e **7,1 kHz → −1 dB**.

Circa un dB. Niente chirurgia.

Confronto EQ acceso e spento, preferisco acceso e mi fermo. La catena finale diventa semplicemente:

**Channel EQ → Adaptive Limiter → Loudness Meter**

Prima dell’export faccio un ultimo passaggio dall’inizio alla fine: controllo che il True Peak non superi il ceiling di **−1 dBTP**, guardo l’Integrated dell’intero brano senza confonderlo con lo Short-Term del drop e tengo d’occhio la riduzione massima del limiter, cioè quanto sta abbassando i picchi. Non ho annotato un Integrated finale abbastanza affidabile da trasformarlo in un numero da esibire, quindi non lo invento: mi interessa che il drop rimanga attorno ai −10 LUFS Short-Term e che il resto della dinamica abbia ancora senso.

Per il bounce finale rimango su **WAV a 24 bit, normalizzazione off**. Non aggiungo dithering perché non sto riducendo il file a 16 bit; le eventuali versioni compresse vengono dopo, partendo da questo master.

Niente compressore multibanda, niente saturatore sul master, niente otto plugin messi in fila perché una thumbnail su YouTube mi ha detto che quello è il segreto del mastering professionale. Se un processore non sta risolvendo un problema, probabilmente non mi serve.

# La parte più importante

Sono partito dicendo che uno dei miei punti deboli è **costruire un suono specifico**. Non posso dire che adesso sappia prendere qualunque cosa abbia in testa e ricrearla perfettamente con un synth. Magari.

Però qualcosa è cambiato. All’inizio vedevo un sintetizzatore soprattutto come un pannello pieno di controlli da muovere finché non succedeva qualcosa di interessante; adesso riesco almeno a scomporre il problema. Posso chiedermi da dove parte il suono, quanto è ricco armonicamente, come si comporta nel tempo, quali frequenze voglio far passare, come voglio farlo muovere e dove deve stare rispetto a tutto il resto.

Oscillatore, forma d’onda e saturazione cominciano quindi a essere modi diversi per rispondere alla domanda *“che materia ha questo suono?”*. Inviluppo, LFO e automazioni rispondono invece a *“come cambia nel tempo?”*. EQ, sidechain e volume servono a capire *“dove deve stare rispetto agli altri?”*. Riverberi, bus e pause diventano infine una questione di *“quanto spazio voglio lasciargli intorno?”*.

Non significa che ora io sappia fare sound design. Significa che almeno **so quali domande farmi**, e forse è già parecchio.

C’è poi l’altra domanda che mi ero posto all’inizio: quanto avrebbe influito il mio stato d’animo sulle decisioni prese durante una lavorazione abbastanza lunga? La risposta è quasi certamente “molto”, anche se non so quanto io sia riuscito ad accorgermene mentre succedeva.

Riascoltando il pezzo riconosco perfettamente alcune scelte che probabilmente non avrei fatto in altri momenti: tensioni molto lunghe, pause, un secondo drop volutamente più aggressivo, una melodia che non cerca di risolvere tutto. Non so quanto di questo sia stato consapevole e quanto sia semplicemente uscito mentre lavoravo.

Probabilmente è anche questo il motivo per cui volevo partire da zero. Il risultato potrà essere grezzo, derivativo, tecnicamente discutibile o tutto insieme, ma almeno quando ascolto qualcosa che non mi piace **è un mio errore**.

E stranamente questa cosa mi piace.

## Cosa mi porto dietro

* Un brano non diventa interessante aumentando continuamente il numero di tracce: anche le pause sono strumenti di arrangiamento.
* Sub e mid bass hanno ruoli diversi; il sidechain è soprattutto gestione dello spazio nel tempo.
* Rivolti e voice leading possono far sembrare accordi diversi parti dello stesso movimento.
* L’automazione può creare evoluzione senza aggiungere continuamente nuove note.
* I bus permettono di separare il suono diretto dai suoi effetti.
* Nel mix conviene partire dagli elementi fondamentali e, prima di aggiungere un plugin, controllare che il problema non sia semplicemente un errore stupido.
* Il loudness non è un punteggio e il mastering non richiede necessariamente quindici processori.
* Un preset che funziona è meglio di tre ore passate a difendere il proprio onore.
* **Saper decidere quando il pezzo è finito è parte del processo creativo.**

Quindi basta.
